# 第 6 阶段：系统写入与询价准入

## 1. 范围

- 供应商主档：33 家卡南加项目导入供应商
- 批次：P0、P1、P2
- 当前实现：前端 Mock 持久化，不接真实数据库和真实审批 API

## 2. 系统写入

人工复核或重复记录归并后，系统将以下信息写入浏览器本地总账：

- 供应商 ID
- 人工复核状态：`pending / approved / rejected`
- 重复记录状态：`not_required / pending / consolidated`
- 询价准入结论：`allowed / needs_review / blocked`
- 阻断原因与风险提示
- 审核人
- 写入时间

本地存储键：

```text
water-price-supplier-human-review-v1
water-price-supplier-duplicate-resolution-v1
water-price-supplier-system-write-v1
```

已有的第 5 阶段审核状态会自动迁移到系统写入总账。

## 3. 询价准入规则

33 家新供应商必须同时满足：

```text
法律主体已识别
AND 人工复核状态 = approved
AND 存在重复来源时已完成归并确认
```

以下情况直接阻断：

- 法律主体未识别；
- 尚未人工复核；
- 人工复核已退回；
- 重复来源记录尚未归并；
- 供应商不在系统主档或统一核验总账。

以下情况允许创建询价，但必须携带警告：

- 仍有缺失字段；
- 仍有已确认的字段冲突；
- 缺少可用联系方式；
- 风险等级较高。

## 4. 二次校验

准入检查执行两次：

1. 供应商库或供应商详情页点击“创建询价”时检查；
2. `/inquiries/create` 生成询价函和创建任务前再次检查。

因此，手工拼接 URL 不能绕过 33 家供应商的准入规则。

## 5. 询价任务写入

创建询价任务时，在 Mock 工作流中保存：

- 询价对象 ID；
- 供应商 ID；
- 每家供应商的准入等级；
- 准入检查时间；
- 尚存警告；
- 询价任务 ID 和比价任务 ID。

供应商资料后续变化不会覆盖已创建任务的准入快照，便于演示追溯。

## 6. 人工判断边界

- AI 只整理证据、冲突、缺失项和风险；
- AI 不直接确认供应商合格；
- 人工复核通过仅表示允许进入询价流程，不表示最终中标或商务采用；
- 正式发送、合同签署和付款仍需后续真实审批系统控制。
