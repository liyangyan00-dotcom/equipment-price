## 2. 统一处理原则

1. 冲突信息不覆盖原值，必须同时保留“原值、候选值、冲突原因、来源链接和查询日期”。
2. 重复记录不物理删除，归并到一个供应商主档，并保留原始 Excel 行号。
3. AI 只生成候选主体、冲突提示、合并建议和优先级，不直接判定供应商合格。
4. P0、P1、P2 使用同一套人工复核状态：`pending / approved / rejected`。
5. 人工通过后才允许创建询价；人工驳回后继续阻断。
6. 法律主体未识别的记录即使人工点击批量通过，也必须继续阻断。
7. “无公开命中”不能写成“无风险”，司法与信用查询必须留存人工查询证据。

## 5. 人工复核流程

1. 打开 `/suppliers/manage` 的“待审核”或“重复记录”页签。
2. 检查候选法律主体和主体消歧状态。
3. 对照原值、候选值、冲突原因和公开来源。
4. 核实工商、联系方式、资质和司法风险四域状态。
5. 重复记录执行“归并主档”，系统保留来源行。
6. 证据充分时选择“人工通过”；证据不足或冲突未解决时选择“退回”。
7. 通过状态写入前端 Mock 本地存储，并在供应商库、详情页和询价入口同步生效。

## 6. 询价准入规则

```text
法律主体已识别
AND 人工复核状态 = approved
→ 允许创建询价
```

以下情况继续阻断：

- 人工复核状态为 `pending`；
- 人工复核状态为 `rejected`；
- 主体状态为 `unresolved_channel`；
- 记录不存在统一核验总账。
